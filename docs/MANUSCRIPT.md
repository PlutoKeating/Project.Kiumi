# 稿件导入与自动排版

从「Word + 相机原图」压缩包到一篇套好风格的图文，全程自动，低把握的地方明确标出让人核对。

## 流程

```
投递包 ZIP（Word + 原图）
  └─ 读取 Word：段落、加粗/字号/对齐、标题样式、自动编号、图片位置
       └─ 结构识别：主标题 / 副标题 / 小标题 / 正文 / 图 / 图注 / 署名
            ├─ 图片匹配：Word 内低清图 → 压缩包原图（原图自动缩放、去 EXIF）
            └─ 排入风格：把稿件按顺序倒进选定的风格模板，套用团队排版规范
```

网页端在浏览器内完成全部步骤，原文件不上传；MCP 端由数据服务完成同样的步骤（见 [MCP.md](MCP.md)）。

## 稿件语义模型

`packages/core/src/manuscript.ts`。导入器先把来源（Word、Markdown、粘贴）压成按顺序排列的 `SourceFact`（文字、加粗、字号、对齐、标题级别、编号前缀、图片引用），再得到：

```
Manuscript { title, subtitle?, byline?{writer,photographer,editor}, sections[{level, heading?, parts[]}] }
parts: p（段落）| figure（一张或多张图 + 图注）| table | list | quote
```

图文顺序以 Word 为准，图片按出现顺序保存在各段之间。

## 结构识别

确定性规则先跑，给出每段的初始角色；网页导入随后请模型复核全文。

| 对象 | 判断依据 |
|---|---|
| 主标题 | 开头 3 段内、较短、无句末标点；居中/加粗/大字加分；Word 一级标题样式直接确认 |
| 副标题 | 紧跟主标题，以「——」开头，或居中的短行 |
| 小标题 | Word 标题样式或大纲级别；手打编号（一、/（一）/1./（1）/第一章…）按出现顺序归一为 1–3 级；加粗或大字的短行 |
| 署名 | 整段以「文：/图：/摄影：/编辑：」开头，或粘在最后一段末尾（自动拆出） |
| 图注 | 图片下方的短行：居中，或以「图 1：」开头 |

段落通过**精简清单**交给模型：`序号|标记|字数|当前角色|内容`（长段只给首尾），模型只回需要改动的 `[[序号, 角色]]`。整篇文章通常只花一两千 token。模型可以是：

- 网页：管理员在 `/admin` 配置的模型（见 [MODELS.md](MODELS.md)，「结构识别」用途），网页送全文清单（`annotationRequest(…, {all: true})`）。没有可用模型或 30 秒内无结果时用规则结果，不影响导入。
- MCP：用户自己的 Agent，经 `kiumi_get_manuscript` 读不确定段落清单、`kiumi_fix_structure` 提交纠正。MCP 流程不调用服务端模型。

## 风格模板填充

`packages/core/src/templatefill.ts`。「风格排版」模板里的文字被替换成「正文」加不可见填充，**填充长度等于原文案字数**，所以只能从样式和长度判断角色。Word 稿件的结构很少和模板一致，所以填充分两步：先定**排版方案**（哪段放进哪个单元），再由同一个执行器落版。

### 1. 模板结构（`analyzeTemplate`）

模板按内容组递归切分：一个块里有多张照片、多段正文，或照片加正文再加别的内容，就继续往下切；横排（flex 行、并排的 inline-block、表格行）保持整体。每个单元归类：

| 类型 | 判断 |
|---|---|
| `title` / `subtitle` | 前几个内容单元里字号明显偏大的文字；紧跟其后的单行短字为副标题。标题单元内字号明显小于主标题（不到 3/4）的标签、胶囊区是副标题位，不放主标题的后半句 |
| `heading` | 只有短文字（4–39 字）的标签条，如「01 活动背景」 |
| `text` | 有 40 字以上文字区的正文区 |
| `photo` / `mixed` | 有样例照片（jpg 或大图；GIF 动图、宽度小于 160px 的小图不算）；带正文的是图文卡片 |
| `decor` | 没有内容，或只有 2–3 字的编号徽标 |

### 2. 排版方案（`PlanEntry[]`）

`{u: 单元号, t: {区号: [稿件编号…] | "拟写文字"}, img: [图片编号…]}`。稿件编号来自 `manuscriptPieces`：`T` 标题、`S` 副标题、`h0…` 小标题、`p0…` 正文、`f0…` 图片、`c0…` 图注、`Y` 署名。同一单元可以重复出现（复制一份），没列出的单元被删除。

- **模型方案**（网页）：浏览器用 `planPrompt` 生成单元与稿件的精简清单（整篇约 1.5–3 千字符），经 `POST /api/manuscript/plan` 交给服务端模型（`/admin`「风格编排」用途）。模型可以给没有对应内容的小标题条拟写短标题（会在预览里列出，请核对），可以重复或跳过单元，让稿件结构贴合模板节奏。覆盖不到 60% 稿件内容的方案视为不可用，改用规则方案。
- **Agent 方案**（MCP）：`kiumi_describe_style` 带 `documentId` 返回同一份清单，Agent 用自己的模型写方案，经 `kiumi_apply_style` 的 `plan` 提交，保存后在换结构或换风格时清除。
- **规则方案**（`autoPlan`）：按稿件顺序为每段找下一个合适的单元：小标题→标签条，正文→正文区或图文卡片，图片→图位数不超过剩余图片的图片单元；模板用完后从第一个小标题条处循环复用。规则不会拟写文字，稿件没有小标题时模板的标签条会被删除。

### 3. 执行（`executePlan`）

- 方案引用的单元首次按原位使用，乱序或重复时用**原始模板标记**克隆到上一个单元之后，连同它前面的分隔、编号徽标；小标题条的编号区自动写 01、02…。
- 填进的正文、图注、署名按团队排版规范写入（正文 14、小标题 16 加粗、黑色、行距 2、字距 2、首行缩进），已有底色或内边距的框里不再加左右边距。模板正文单元本身是 `<p>` 时改为 `<section>` 再写入，不嵌套段落、不保留模板段间距。
- **除大标题外所有写入的文字都服从规范**：写进模板标签条、胶囊的小标题、副标题、拟写标签、短图注去掉模板的颜色、字体、行距、字距，改为黑色、秀米默认字体（不继承模板 `font-family`）、行距 2、字距 2；小标题改为 16 加粗，其余短行保留该区字号。唯一例外：模板把浅色字压在色块上的标签条保留原字色，否则黑字会看不见。大标题沿用模板样式，不加粗的补加粗。
- 没用到的文字区连同它的标签框、底色条一起删除；没用到的单元连同它前面的装饰删除，删空的外层容器逐级删除；模板开头和结尾的页眉、页脚装饰保留。
- 标题只写进与主标题同等字号的区：有两个这样的区时在逗号（规范里已改成空格）处分成两半；只有一个区且标题比模板原文案长时在同一位置换行。副标题写进标题单元里的小字区时去掉开头的「——」；模板完全没有副标题位时，副标题以小标题字号、加粗、居中、黑色排在正文之前，不算「放不下」。
- 图文之间空行按最终版面的阅读顺序检查：每组稿件照片（并排的多张算一组）紧挨着正文或另一组照片时补一个空行，模板自带的空行、分隔装饰不重复补；照片和正文分处同一张卡片的不同层级时同样生效。最后统一整理空行：两段文字（含小标题）之间的空行删除，连续两个空行合并为一个，全文开头和结尾各保证一个空行；大标题单元内部的间距按模板保留。
- 单张照片本身宽 90%（`width:90%`，居中），外层按像素定宽的图框改为占满图位，90% 以图位为准；并排多张的照片各自占满所在列。模板常把整张卡片 `rotateY(180deg)` 再在内部翻回来，替换内容后内层翻转消失，所以所有承载文字或照片的元素都会去掉 180° 旋转与镜像，纯装饰保持原样。
- **内容不丢失**：方案没放下的段落、图片（模板没有图片位、单元不够、编号写错或重复）按排版规范排在它在稿件中的前一项旁边；最后再按文字与图片地址核对一遍全文，缺什么补到末尾。报告的 `spilled` 计数并提示核对版面。
- 模板没有标题位时，标题只作为图文标题（公众号本身显示）不进正文。

报告 `FillReport` 含 `plan`（`model` / `agent` / `auto`）、`generated`（拟写的标签）、`spilled`、`clonedUnits`、`removedUnits`、`warnings`。没有风格模板时用 `plainArticle` 生成纯文字排版。

## 原图匹配

`packages/core/src/imagematch.ts`，浏览器用 canvas、数据服务用 sharp 取 32×32 灰度缩略图后交给同一份算法：

- dHash + 均值哈希 + 16 档亮度直方图，宽高比不符扣分，原图按文件名（相机拍摄顺序）作为并列时的先验。
- 一个占位图可对应同一张原图多次；压缩包里没出现在 Word 中的原图进入团队图库，不入文。
- Word 里有图但压缩包里没有对应原图时，使用 Word 内嵌图并标黄提示补充。
- 把握低（`low`）的项在导入预览里标黄，可逐张下拉改选；MCP 返回同样的候选列表。
- 原图统一缩到长边 2000 px、JPEG 质量 85，EXIF（含 GPS）被去除；超过 10 MB 的相机原图因此可以直接使用。

## 团队排版规范

`packages/core/src/typeset.ts`。规范是数据（`TypesetRules`），团队创建者保存在 D1（`teams.typeset_rules`），成员只读。填充、`lintBlocks`（右侧「图文」面板、`kiumi_lint`）共用同一份，改一处即全部生效。

默认值来自现行规范：正文 14 / 小标题 16 加粗 / 黑色 / 行距 2 / 字距 2 / 段间距 0 / 边距 20 / 首行缩进 / 图宽 90% / 图文之间空行 / 长标题截断。检查项：深灰文字、字号与行距、图片宽度、用连续回车造的空行、段首空格缩进、图文之间缺空行、标题过长。

## 验证

```bash
pnpm test                                  # core：识别、填充、图片匹配、规范；data：ZIP 导入
pnpm --filter @kiumi/web test:e2e          # 浏览器：ZIP → 匹配 → 排入风格 → 实时更新
```

真实投递包（不入库）：

```bash
KIUMI_ZIP_SAMPLE=/path/稿件.zip KIUMI_STYLE_RECORD=/path/shop__paper__NNN.json \
  pnpm --filter @kiumi/web exec playwright test manuscript.spec.ts -g "local submission"
```
