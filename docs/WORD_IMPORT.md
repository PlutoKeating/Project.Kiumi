# Word / WPS 导入

## 工作流

1. 在「导入内容」选择 `.docx`，或粘贴 Word/WPS 富文本。旧版 `.doc`、`.wps`、RTF 必须先另存为 `.docx`。
2. 有图片时，先登录并选择团队。文档在浏览器解析，原始 Word/ZIP 不发送到服务端或第三方。
3. 预览标题、正文、图片、表格和列表块。可将疑似标题改为正文或 1–6 级标题。
4. 对无法可靠转换的内容，查看位置和处理说明，勾选接受转换结果后才能继续。取消不会改变文稿。
5. 选择追加末尾、选中块之后或新建文稿。确认后逐张上传图片到现有团队图库，全部成功才写入画布。新建前先保存当前团队文稿；保存失败不切换。
6. 导入可一次撤销；已上传图片保留在图库。中途失败可重试，当前预览中成功上传的图片不会再次上传。

图片 ZIP 单独批量进入图库，不自动匹配正文位置。空 ZIP 明确报错，非图片文件列入跳过清单。

## 内容支持与降级

| 内容 | 行为 |
|---|---|
| 中文、Unicode、段落 | DOCX 解压后解析 XML，不把二进制当文本；每段一个块 |
| 标题 | 使用标题样式、继承的大纲级别识别；1–6 级保留，7–9 级按六级显示并提示 |
| 仅加粗或大字号的疑似标题 | 提示人工确认，预览可调整层级；不保证识别所有自定义样式 |
| 粗体、斜体、下划线、删除线、上下标、链接 | 保留语义，字体和间距按公众号样式统一 |
| 独立图片 / 行内图片 | 独立图成块；行内图保留在段落；多张无文字的图片段拆开 |
| 浮动图 / 图注 | 图按锚点落位并提示不保留环绕；图注保持文档顺序，不推测配对 |
| 表格 | 完整表格块，保留内容与合并关系，统一边框、宽度和换行；多列表格提示检查。可改文字，暂不提供行列增删、合并拆分工具 |
| 列表与编号标题 | 使用 OOXML 编号定义、起始值和层级生成可见编号，再组合列表块；常见数字、字母、罗马数字及百位以内中文编号支持。其他格式、缺少定义时提示核对 |
| 脚注、尾注 | 由 Mammoth 转换为文末注释和内部链接；实际公众号客户端的内部跳转仍需人工验收 |
| 修订、批注 | 按接受修订后的正文导入，批注不进入正文并提示；粘贴入口仅能处理剪贴板实际提供的修订信息 |
| 公式 | 目前将 OMML 线性文字保留在原位置的待核对标记中；不声称保留分式、矩阵等公式结构，可取消并准备公式图片 |
| 文本框 | 提取文字，按锚点附近正文显示并提示；不保留浮动外框 |
| 图表、SmartArt、嵌入对象 | 优先使用文档提供的兼容内容/静态图；没有可用内容则标记待补充并提示。不能编辑原生图表数据 |
| 页眉、页脚 | 提取文字追加在正文末尾，不重复分页；其中图片或表格需另行补充，并显示标记 |
| 目录 | 保留文件中已存储的文字，提示核对旧页码，不重新计算目录 |
| 不支持的嵌入内容 | 可识别的对象保留位置标记，解析器其他警告进入预览清单；不能保证任意 OOXML 扩展完整还原 |

Word/WPS 剪贴板可能只提供本地图片路径，没有图片字节。此时放置缺图标记并建议使用 DOCX。只有一张本地图和一张剪贴板图片时才自动匹配，多张时不猜测对应关系。网络图需浏览器可读取（受 CORS 限制），失败进入清单。ZIP 中的图片始终由用户手动插入。

HTML 文件/网页沿用原有保留布局和 SVG 的流程，避免 Office 样式归一化破坏已有 HTML 导入能力。Markdown 按语义生成文章块。

## 大小、存储与失败边界

- 典型验收规模：1–20 页、30 张图片以内。
- 图片总量上限 80 MiB，按解压后的图片字节计算；单张仍遵循现有上传 API 的 10 MiB 上限，超限图片明确提示。
- 输入 DOCX/ZIP 上限 100 MiB，最多 2,000 个文件条目；解压总量 128 MiB，单 XML/普通条目默认 20 MiB。ZIP 流式读取时计数，避免仅检查压缩后的大小。
- 文本输入上限 20 MiB（粘贴按字符数），支持 UTF-8 和带 BOM 的 UTF-16；无效编码明确报错，不以替换字符继续导入。
- 预览用临时 Blob URL，离开预览释放；正式文稿只记录上传后的地址，不保存临时 URL 或大段图片 Base64。
- 图片上传与画布写入分开：图片全部成功后一次提交画布。取消/失败时可能已有图片入库，界面明确告知；不自动删除团队图库资源。
- 预览与上传绑定账号/团队，切换后不能继续提交。上传支持取消；原始文档不会交给服务端转换。

## 实现边界

- `apps/web/src/lib/word-import/archive.ts`：受大小限制的 ZIP 读取。
- `docx.ts`：Mammoth 前置兼容处理、编号、复杂内容提示和图片提取。
- `index.ts` / `model.ts`：统一预览、分块、Office 粘贴、资源生命周期、确认后上传。
- `ImportPanel.tsx`：预览、问题确认、标题调整、导入位置、取消/重试。
- 正式文稿复用现有 `library` HTML 块和 `/api/assets/upload`，不新增后端转换服务或数据模型版本。
- Mammoth 与 JSZip 按需加载；解析库输出仍经过 HTML 清理。

## 验证

```bash
pnpm typecheck
pnpm test
pnpm --filter @kiumi/web test:import
pnpm build:web
```

首次运行浏览器测试需安装 Chromium：`pnpm --filter @kiumi/web exec playwright install chromium`。

浏览器回归覆盖：DOCX 乱码与分块、Office 粘贴、合并表格、缺图提示、编号、修订、脚注、复杂内容标记、ZIP 总量限制、预览不改稿、上传失败、账号隔离、编辑/保存恢复、复制/导出、整次撤销、插入位置和新建保护。Worker/D1 测试覆盖分块存取、签名图片外部读取和草稿服务收到完整正文；微信服务在测试中被替身替代，不代表真实公众号已验收。

可用环境变量 `KIUMI_WORD_SAMPLE` 指向本机 Word 文件运行可选样本测试；`KIUMI_WORD_SCREENSHOT` 指定截图输出位置。样本和截图不加入仓库。正式发布前仍需使用实际 Word/WPS 粘贴环境、典型复杂稿件和真实公众号完成验收。

## 上传恢复

仅网络错误和 500/502/503/504 自动重试两次（间隔 0.5 秒、1.5 秒），取消和权限/格式/大小错误不重试。成功上传进度保留；服务端按团队和图片内容去重，避免响应丢失后再次登记。失败提示包含图片序号和文件名。图片全部成功后仍只提交一次画布，画布立即本地渲染，不再逐块等待网络。
